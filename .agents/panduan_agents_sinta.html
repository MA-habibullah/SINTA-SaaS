1. Standar Arsitektur Modular & PostgreSQL Multi-Schema

  • Struktur Direktori & Namespace: Seluruh modul berlokasi di app/Modules/[NamaModul]/. Controller menggunakan namespace App\Modules\[NamaModul]\Controllers; dan Model menggunakan namespace App\Modules\[NamaModul]\Models;.
  • Pendefinisian Model PostgreSQL: Model wajib mendefinisikan prefix skema secara eksplisit (contoh: protected $table = 'sistem.nama_tabel';). Terapkan tipe data cast yang sangat ketat untuk tipe Boolean, Integer, dan JSON.
  • Batasan Controller: Controller wajib menggunakan BaseController & jsonResponse() serta Prepared Statements PDO tanpa mencampur kueri kotor langsung.
🛡️

2. Security Guidelines (Anti-XSS & Protection)

  • Pencegahan Kebocoran Kredensial: Hapus data sensitif (hash password, token, api_key) menggunakan unset() sebelum dikirim ke sisi klien.
  • Anti-XSS pada Tag Script: Selalu gunakan bendera JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT saat mencetak json_encode() di dalam tag <script>.
  • Anti-XSS pada Atribut HTML: Wajib membungkus data JSON atribut HTML dengan htmlspecialchars(..., ENT_QUOTES, 'UTF-8').
  • Pencegahan SQL Injection: Gunakan Prepared Statements dengan Parameter Binding PDO. Dilarang menggabungkan variabel langsung ke string SQL.
⚡

3. Modern Architecture & Zero Data Leakage

Hindari mencetak data mentah dari database langsung ke HTML via PHP json_encode. Pemuatan data wajib menggunakan Dynamic AJAX Fetch Asinkronus pada saat komponen ter-mount di sisi klien untuk mencegah data bocor lewat "View Page Source" (Ctrl+U).

💡
Standardisasi Respon API JSON: Selalu gunakan format terstandardisasi: ['success' => true/false, 'data' => ..., 'error' => ...] dengan HTTP status code yang tepat (200 OK, 400 Bad Request, 403 Forbidden, 422 Unprocessable Entity).
🔄

4. Fast-Track Migration Cheat Sheet (MySQL ➔ PostgreSQL)

Kebutuhan SQL MySQL Syntax (Legacy / Dilarang) PostgreSQL Syntax (Wajib Gunakan Ini)
Paginasi Data LIMIT offset, count LIMIT count OFFSET offset
Pencarian Case-Insensitive WHERE name LIKE '%abc%' WHERE name ILIKE '%abc%'
Dapatkan ID Baru LAST_INSERT_ID() RETURNING id (pada query INSERT)
Tanggal & Waktu NOW() / CURRENT_TIMESTAMP CURRENT_TIMESTAMP / NOW()
Tipe Data Boolean 1 / 0 atau '1' TRUE / FALSE (Strict Boolean)
Filter Data JSON JSON_EXTRACT(col, '$.key') col->>'key' (text) atau col->'key' (json)
Upsert (Insert / Update) ON DUPLICATE KEY UPDATE ON CONFLICT (target) DO UPDATE SET ...
Inspeksi Struktur Tabel SHOW COLUMNS FROM tbl Kueri information_schema.columns
Prefix Skema nama_tabel skema.nama_tabel (misal: siswa.buku_induk)

5. Template Standar Fast-Development

Template Controller Modular

app/Modules/[NamaModul]/Controllers/[NamaModul]Controller.php 
<?php
namespace App\Modules\[NamaModul]\Controllers;

use App\Core\BaseController;
use App\Modules\[NamaModul]\Models\[NamaModul]Model;
use Exception;

class [NamaModul]Controller extends BaseController
{
    private $model;

    public function __construct()
    {
        parent::__construct();
        $this->model = new [NamaModul]Model();
    }

    public function index()
    {
        try {
            $tenantId = $this->getSecureTenantId();
            $data = $this->model->getAllByTenant($tenantId);
            return $this->jsonResponse(['success' => true, 'data' => $data], 200);
        } catch (Exception $e) {
            return $this->jsonResponse(['success' => false, 'error' => $e->getMessage()], 500);
        }
    }
}

Template Model Modular

app/Modules/[NamaModul]/Models/[NamaModul]Model.php 
<?php
namespace App\Modules\[NamaModul]\Models;

use App\Config\Database;
use PDO;

class [NamaModul]Model
{
    protected $db;
    protected $table = '[skema].[nama_tabel]';

    public function __construct()
    {
        $this->db = Database::getConnection();
    }

    public function getAllByTenant(string $tenantId): array
    {
        $stmt = $this->db->prepare("SELECT * FROM {$this->table} WHERE tenant_id = :tenant_id AND deleted_at IS NULL ORDER BY created_at DESC");
        $stmt->bindValue(':tenant_id', $tenantId, PDO::PARAM_STR);
        $stmt->execute();
        return $stmt->fetchAll(PDO::FETCH_ASSOC) ?: [];
    }
}

7. Aturan Dokumentasi Rencana & Walkthrough Harian

Seluruh catatan rencana implementasi dan walkthrough hasil akhir wajib dicatat ke dalam satu file harian di scratch/docs/:

  • Fitur Baru / Refactoring Arsitektur Besar: Wajib menyertakan seluruh konten rencana & walkthrough secara lengkap verbatim.
  • Perbaikan Bug Kecil / Minor Tweaks: Cukup gunakan format Compact Log (10-25 baris) yang mencakup Root Cause + Files Changed + Solution + Quick Verification Result untuk mempercepat alur pengerjaan.
💾

8. Database Migration Rules (Format Return Array)

Seluruh file migrasi di database/migrations/ wajib menggunakan format return [...] array agar migrate.php dapat mengeksekusi dan mencatat migrasi ke tabel migrations.

✅ Format Migrasi Benar (database/migrations/YYYY_MM_DD_NN_deskripsi.php) 
<?php
return [
    'up' => function (PDO $pdo): void {
        $pdo->exec("ALTER TABLE skema.nama_tabel ADD COLUMN IF NOT EXISTS nama_kolom VARCHAR(255)");
        echo "- Kolom berhasil ditambahkan.\n";
    },
    'down' => function (PDO $pdo): void {
        $pdo->exec("ALTER TABLE skema.nama_tabel DROP COLUMN IF EXISTS nama_kolom");
    },
];
